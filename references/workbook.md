# 洞见卡操作指南

此指南用于把材料加工成可调用的判断。它提供操作设计，不代替具体材料的证据。
例子全部虚构；案例中的记录仅用于演示如何推理，不代表技能效果实测。

## 1. 先决定是否成卡

把候选句改写为“当出现条件 C 时，做 A，以观察 R”。
若 C、A、R 都无法说明，先留作摘录或问题，不强行成卡。
若它只是事实定义，可以成为参考条目；不要补出不存在的行动因果。
若只有情绪或评价，追问导致评价的事件及可观察差异。
判断卡片粒度时使用“独立失败测试”：一个动作失败而另一个成功时，是否需要两套解释？
需要两套解释就拆卡；属于同一动作的前提、步骤和停止条件留在一张卡内。

| 候选材料 | 处理 | 理由 |
| --- | --- | --- |
| 沟通要清晰 | 暂不成卡 | 无法判断哪个动作会改变 |
| 提问前附复现输入，便于定位问题 | 可成候选卡 | 有触发、动作和观察项 |
| 既要提问又要每天运动 | 拆分 | 两条不相干的作用链 |
| 提交请求前检查输入是否完整 | 保留检查项在同一卡 | 检查直接服务同一请求 |

## 2. 做一份证据账本

先摘出最短的必要事实，再写解释；避免解释倒灌成事实。
每行只放一种性质的信息，缺日期或定位时直接注明缺失。

| 类型 | 应记录什么 | 不能据此声称什么 |
| --- | --- | --- |
| 用户报告 | 场景、行为、结果、报告日期 | 已独立核实、必然因果 |
| 材料论述 | 文件或段落、主张、支持理由 | 主张已经普遍成立 |
| 加工推断 | 推断链、可替代解释 | 材料明确提出了该解释 |
| 拟议实验 | 计划动作与观察项 | 动作已执行或取得效果 |

原始记录与加工稿分开保存。对无法回查的转述，降低结论强度，不补造链接。
多个案例若来自同一次事件或同一转述链，不当作独立证据。

## 3. 写出可被反驳的机制

用“动作 → 中间变化 → 结果”写两到三个环节。
对每个箭头问：记录里看见了吗，还是仅仅合理？
没有观察到的箭头用“可能”“待验证”标明。
再列一个替代解释：结果可能由时间、样本难度、权限或人员变化造成。
优先选择能够区分两种解释的观察项，而非只记录最终满意度。
例如“回复更快”无法区分输入完整与接收者当天更空闲；补记澄清轮数更有帮助。
仍无法区分时，保留相关性判断，不声称机制已经证实。

## 4. 用强反例收窄范围

先找与主张最接近、却可能失败的场景，不只写极端例外。
依次检查：必要条件缺失、动作成本过高、目标冲突、尺度变化。
若反例只影响一个条件，把条件加入卡片。
若反例表明动作与目标无关，放弃该判断，保留问题或失败记录。
反例不是装饰句；它应改变触发条件、操作或停止标志中的至少一项。

## 5. 可填写卡片模板

```text
标题：
核心判断：当____时，尝试____，观察____。
来源定位与日期：
已观察事实：
机制假设：动作____ → 中间变化____ → 结果____。
缺证据环节与替代解释：
执行步骤：
完成标志 / 停止标志：
适用条件：
强反例及因此收窄的条件：
关联旧卡及关系：互补 / 冲突 / 前置 / 具体化 / 暂无。
状态及依据：候选 / 单场景使用 / 多场景使用。
下一次验证：观察____；若发生____，改为____。
```

模板中的空栏表示待填写输入，最终交付不要留下无说明的空白。
没有旧卡填“暂无”；没有验证结果填“未执行”，不为了完整性编造。

## 6. 完整虚构实例：交接信息缺失

虚构输入：某小组在演练记录中写到，两次交接只说“页面报错”，接手人各追问两轮。
第三次交接附了输入文件版本和错误发生步骤，接手人没有追问；三次任务难度不同。

标题：交接故障时先给可复现入口。
核心判断：异步交接可复现故障时，先附输入版本与触发步骤，可能减少补问。
来源定位：虚构演练记录 A 的第 1—3 条，无真实文件或日期。
已观察事实：演练设定中，两次简略交接发生补问，一次较完整交接未补问。
机制假设：输入明确 → 接手人能尝试复现 → 无需先补问背景。
缺证据：没有记录复现是否成功；第三次问题也可能本来更简单。
动作：下次交接附输入版本、三步以内的触发过程和实际错误表现。
完成标志：接手人能定位同一输入并开始复现；停止标志：无法获得合法可分享的输入。
边界：仅适用于可复现且允许分享输入信息的故障，紧急处置可先报告影响再补材料。
强反例：故障由接手人缺权限引起，补充步骤不能解决权限问题。
关联：暂无已读取旧卡。
状态：候选；虚构演练不能充当真实应用证据。
下一次验证：记录是否可复现、补问原因与任务难度；若仍卡在权限，补充权限前置检查。

## 7. 旧卡更新与验收

更新前先写一句差异：“旧卡在 X 条件下失败，因此把范围收窄为 Y”。
若新证据只证明操作不完整，就改步骤，不自动推翻全部机制。
若出现相反结果，保留两组证据与条件，不能只留下成功样本。
只有使用记录跨越了不同条件，才考虑从单场景升级为多场景使用。
“读了五遍”“生成十个例子”不构成使用次数。

验收时遮住标题，检查正文是否仍能指导一次动作。
用反例代入：读者能否知道何时停止或换方法？
沿来源查回：事实、推断、实验是否仍清楚分离？
如果删掉一个句子不影响判断、执行或核查，就考虑删掉它。
最终卡片以足够使用为准，不以长度、卡片数量或措辞新奇为准。
